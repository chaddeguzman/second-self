# Charlie — Runtime Contract

> What Charlie needs from the runtime to function. If any requirement is
> missing, Charlie reports `Blocked: missing tool X` instead of silently
> failing. This file is the spawn instruction for any runtime standing
> up a Charlie session.

## Required capabilities

| Capability | Why Charlie needs it |
|------------|---------------------|
| File read/write | Read SKILL.md, log.md, wip.md, patterns.md, shared/context.md; write results and status updates |
| Shell/command execution | Run tests, run the built code, verify behavior |
| Git access | Commit incrementally, use feature branches for large work |

## Required context files

| File | Purpose |
|------|---------|
| `SKILL.md` | Who Charlie is, how he works |
| `log.md` | Task queue and history |
| `wip.md` | In-progress build state (if present) |
| `patterns.md` | Accumulated patterns and anti-patterns |
| `../shared/context.md` | Current mission context from ECHO |

## Boot prompt (dynamic — generated by ECHO at delegation time)

The boot prompt is **not a static string** — ECHO generates it dynamically
each time she delegates. The flow:

1. Chad says "ECHO, build a CLI" → ECHO writes the task to `log.md` (Pending)
2. ECHO spawns a Charlie session with a boot prompt that:
   - Establishes Charlie's identity and points to SKILL.md
   - References the task entry just written to log.md
   - Instructs Charlie to run the boot sequence, then accept the task

### Boot prompt template (ECHO fills in `[task entry]` at delegation time)

```text
You are Charlie, ECHO's development sub-agent.
Your operating rules live in 90-system/.echo/subagents/charlie/SKILL.md.

A new task is waiting in your log.md — the most recent entry at the bottom.
Run your boot sequence now (per your SKILL.md), then accept the task and
begin working. Report back when you hit a checkpoint or need input.
```

ECHO appends the log row *before* spawning, so Charlie's first act is to
read a log that already contains his assignment. No static message needs
to carry the task — the log is the source of truth.

## Verification (built into boot, not operator checklist)

The boot prompt's step 0 is always **capability self-check**:
"If any required tool is missing → log status: `Blocked: missing tool X"`

This is self-verifying — if Charlie comes back with a status line and
starts working, the runtime is wired. If he reports `Blocked`, ECHO
escalates to Chad. No separate operator checklist needed.
