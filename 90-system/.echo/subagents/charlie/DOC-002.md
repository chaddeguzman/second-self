# DOC-002 — Future-Proof Gmail and Drive Capability Contracts

Status: Done
Owner: Charlie
Priority: 3
Endorsement: ECHO
Start trigger: `Charlie do assignment DOC-002`

## Purpose

Preserve Gmail and Drive as future ECHO capabilities without allowing
unfinished integrations to weaken Second Self's privacy, recall, evidence, or
approval boundaries.

## Agreed direction

- Read-only and on-demand first.
- Disabled by default.
- No background synchronization.
- No automatic ingestion into Layer 1 or the wiki.
- No external writes, sends, uploads, moves, renames, labels, or deletes.
- A result is transient unless Chad explicitly requests a save.
- An explicit save must enter `01 Capture/00 Raw` through the existing broker
  and review flow.
- OAuth tokens belong in the operating-system keyring and never in Git,
  logs, CI output, or capability health summaries.
- Provider failure must degrade gracefully and leave core Second Self recall
  and local workflows operational.

## Planned contract shape

```text
ECHO request
  -> capability/status check
  -> disabled or unavailable: explain status and stop safely
  -> available: bounded read-only connector request
  -> transient redacted result
  -> answer with source/provider attribution
  -> explicit save only: broker-reviewed Raw capture
```

The capability registry should distinguish `planned`, `disabled`, `available`,
and `degraded`. The connector interface should return typed metadata and
source attribution rather than provider-specific payloads. Gmail and Drive
must remain replaceable adapters behind that interface.

## Non-goals

- Implementing OAuth in this assignment.
- Calling Gmail or Drive from CI.
- Adding provider credentials or private data fixtures.
- Replacing the local Second Self vault with cloud storage.
- Building autonomous email, calendar, or file-management actions.
